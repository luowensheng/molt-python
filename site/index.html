Under the hood

How molt run works

No venv activation. No source .venv/bin/activate. Just exec.

1

Load syspath.json

Read the project's .molt/syspath.json — interpreter path and ordered list of store directories.

2

Build PYTHONPATH

Set PYTHONPATH=.molt:store_dir_1:store_dir_2:… pointing at the global package store entries.

3

Prepend .molt/bin

Console-script shims (black, pytest, …) live in .molt/bin/. Prepend it to PATH.

4

Strip isolation vars

Unset VIRTUAL_ENV and PYTHONHOME so no external activation leaks in.

5

syscall.Exec

Replace the molt process with the interpreter or binary — zero overhead, no child process, correct signal handling.

~/.molt/ ├── pkg/ │ ├── requests/2.32.3/py3-none-any/ # shared across all projects │ ├── fastapi/0.111.0/py3-none-any/ │ ├── black/24.4.2/cp312-cp312-macosx_11_arm64/ │ └── numpy/1.26.4/cp312-cp312-macosx_11_arm64/ ├── python/ │ └── 3.12.3/ # standalone interpreter └── registry.json # GC manifest myproject/ ├── pyproject.toml ├── uv.lock └── .molt/ ├── syspath.json # interpreter + store dirs ├── sitecustomize.py # handles .pth files └── bin/ ├── black # console-script shim └── pytest
The global store is content-addressed. Install requests in 10 projects — it lives on disk exactly once at ~/.molt/pkg/requests/2.32.3/py3-none-any/. Every project's PYTHONPATH points at the same directory.

Native hot paths

Speed up Python without changing languages

Python is excellent for orchestration. When the bottleneck is a CPU-bound inner loop, drop in a C, C++, Zig, or Mojo hot path — molt compiles and wires it up automatically. Keep Python for everything else.

📈

Typical speedups

Float loop (10M)20–40×
C++ std::sort (1M)5–15×

Math primitives30–100×

The gradient of effort

Pick the strategy that matches the speedup you need.

Python pure → 1× no build
Cython → 2–10× .pyx file
C extension → 5–100× .h header
C++17 STL → 10–80× subprocess or extern "C"
Zig / Mojo SIMD → 50–500× vectorised

Cross-platform from one machine

zig cc cross-compiles C/C++/Zig for any target from your dev machine — no Docker, no remote SSH.

# macOS → Linux binary
zig cc -target x86_64-linux-gnu \
  -O2 -o bin/app-linux src/main.c

# Full molt project, cross-compiled
molt build --os linux --arch amd64

The workflow: profile → drop in native → sync

# 1. Find the bottleneck
molt exec python -m cProfile -s cumulative main.py | head -20

# 2. Add a C extension — just a header + one toml stanza
#    molt auto-generates PyInit_ / PyMethodDef / Py_BuildValue boilerplate
[[tool.molt.c.modules]]
header  = "fastsum.h"
sources = ["fastsum.c"]

# 3. Compile + wire up in one command
molt sync

# 4. Call it — no restart, no pip install .
python -c "import fastsum; print(fastsum.sum_f64(data))"

10 — Mojo SIMD vectorization

Mojo SIMD types, vectorized operations, hardware-width detection, and benchmarking against pure Python. Shows where Mojo's speed advantage comes from: SIMD processes N values per CPU instruction without GIL overhead.

  • Manual SIMD while-loop — 4×/8× throughput vs scalar
  • Hardware SIMD width detection at runtime
  • Head-to-head benchmark vs Python loop
  • Element-wise addition on 1M float32 values
Full walkthrough → 
# simd.mojo
alias WIDTH = 8  # 8× float32 = 256-bit AVX2

fn add_simd(a: DTypePointer[dtype],
            b: DTypePointer[dtype],
            c: DTypePointer[dtype], n: Int):
    var i = 0
    while i + WIDTH <= n:
        c.store(i, a.load[WIDTH](i) + b.load[WIDTH](i))
        i += WIDTH
$ molt run bench

Mojo SIMD×8: 18 ms (47× faster)

15 — Run and manage C projects

Two capabilities: molt run hello.c compiles with zig cc and executes in one command — no config, no Makefile. Multi-file C projects are managed with pyproject.toml tasks (build, run, clean) — same workflow as any Python project. Python orchestrates the C binary in the same project.

  • Single-file: molt run hello.c Alice → compile + exec, args forwarded
  • Multi-file: molt run build → cc -O2 → bin/stats
  • Python drives C: molt run demo → subprocess to the binary
  • C and Python share the same molt project, same tasks, same molt run
Full walkthrough → 
/* hello.c — no config needed */
#include <stdio.h>
int main(int argc, char *argv[]) {
    printf("Hello from C! 👋 %s\n",
           argc > 1 ? argv[1] : "World");
}

# pyproject.toml tasks
[tool.molt.tasks]
build = "cc -O2 -o bin/stats src/main.c src/stats.c -lm"
stats = "bin/stats"
demo  = "python demo.py"
clean = "rm -f bin/stats"
$ molt run hello.c Alice
Hello from C! 👋 Alice
$ molt run build
✓ compiled bin/stats
$ molt run demo

// hello.zig — Zig 0.16 API
const std = @import("std");
pub fn main(init: std.process.Init) !void {
    const arena = init.arena.allocator();
    const args = try init.minimal.args.toSlice(arena);
    const name = if (args.len > 1) args[1] else "World";
    var buf: [256]u8 = undefined;
    const msg = try std.fmt.bufPrint(&buf,
        "Hello from Zig {s}! 👋 {s}\n",
        .{ @import("builtin").zig_version_string, name });
    try std.Io.File.stdout().writeStreamingAll(init.io, msg);
}

Get started

Install molt

A single static binary — no Go runtime, no dependencies.

Download the binary for your platform from GitHub Releases, put it on your PATH, and you're ready to go. molt itself has no runtime dependencies.

molt requires uv for dependency resolution — it will be auto-downloaded on first use if not present.

↓  Download latest release

Available for macOS (arm64, amd64), Linux (amd64, arm64), Windows (amd64).
SHA-256 checksums provided for all artifacts.

1

Download the binary

Pick your platform from the Releases page and download molt-<os>-<arch>.

2

Put it on your PATH

chmod +x molt-darwin-arm64
mv molt-darwin-arm64 /usr/local/bin/molt
3

Verify & add ~/.molt/bin to PATH

molt --version
# Add to ~/.zshrc or ~/.bashrc:
export PATH="$HOME/.molt/bin:$PATH"
4

Create your first project

molt init myapp
cd myapp
molt add requests
molt run python
