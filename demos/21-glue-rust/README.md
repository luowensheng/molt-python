# Demo 21 — Transport Glue: Rust, unix_socket

Calls Rust compression functions (via flate2) from Python using a persistent
**unix_socket** server. Multiple Python threads share one Rust process.

## Layout

```
21-glue-rust/
  compress_glue.rs      ← thin Rust adapter (NOT a full crate; pub fn only)
  compress.molt.toml    ← glue manifest
  moltproject.toml
  main.py
```

## Key config

```toml
# compress.molt.toml
lang      = "rust"
src       = "compress_glue.rs"
crates    = ["flate2 = '1.0'"]
transport = "unix_socket"

[[fn]]
name    = "deflate"
args    = [{ name = "data", type = "bytes" }]
returns = "bytes"

[[fn]]
name    = "inflate"
args    = [{ name = "data", type = "bytes" }]
returns = "bytes"

[[fn]]
name    = "ratio"
args    = [{ name = "data", type = "bytes" }]
returns = "f64"
```

## How `include!` works

`compress_glue.rs` is not a Cargo project — it's a plain file with `pub fn`
declarations. molt generates a full `main.rs` that pulls it in:

```rust
// Generated by molt
include!("../../../../compress_glue.rs");  // ← your functions are now in scope

fn dispatch(req: &Value) -> Value {
    match fn_name {
        "deflate" => { ... deflate(data) ... }
        ...
    }
}
```

The generated `Cargo.toml` adds `flate2 = "1.0"` from the `crates = [...]` config.

## Transport: unix_socket

Unlike `stdio` (subprocess per Python process), `unix_socket` runs the server
as a persistent daemon. The Python client:

1. Checks for the socket file on first call.
2. If absent, launches the server with `MOLT_GLUE_SOCK=/tmp/molt-glue-compress-<pid>.sock`.
3. Reconnects to the socket for every call — no global state, concurrency-safe.

## Run

```sh
molt sync          # compile Rust server (cargo build --release), generate compress.py
molt run demo      # python main.py
```

Manual server management (optional):
```sh
molt glue start compress    # start the daemon explicitly
molt glue stop  compress    # stop it
```
