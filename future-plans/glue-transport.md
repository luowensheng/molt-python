# Transport Glue — Design Document & Sample Projects

Call Go, Rust, or any compiled language's functions from Python **without writing a
single line of C or FFI boilerplate.** Declare the functions you need in
`moltproject.toml`; `molt sync` generates the server binary and the Python module that
talks to it.

---

## The problem it solves

Calling Go or Rust from Python via `.so` breaks on real-world code:

| What you want to call | Problem with `.so` |
|---|---|
| `http.Get(url)` (Go stdlib) | Returns `*http.Response` — not a C-ABI type |
| `sha3.Sum256(data)` | Returns `[32]byte` array — not directly expressible in C |
| Rust `Vec<String>` output | Requires manual FFI marshalling through C strings |
| Any function using Go interfaces | Cannot be exported as `//export` |
| Rust `async fn` | Cannot cross the FFI boundary |

**Transport Glue** sidesteps this entirely: the Go/Rust code runs in its own process as a
tiny JSON-RPC server. Python calls it through a generated client module. No ABI
compatibility required — just JSON over a pipe, socket, or TCP connection.

---

## How the generated server imports your code

The generated server file is **not compiled together with your source**. It lives in its
own mini Go module and imports your package through a `replace` directive in `go.mod`.
This means your code stays a proper, importable Go package — not `package main`.

```
project-root/
  stats/
    stats.go                ← package stats  (you write this — NOT package main)
  moltproject.toml
  main.py

.molt/
  _build_stats/             ← temporary build dir created by molt sync
    go.mod                  ← generated: module + replace → project-root/stats
    server.go               ← generated: package main; imports "user/stats"
  stats_server              ← compiled binary
  stats.py                  ← generated Python client
  stats.pyi                 ← typed stubs
```

**Generated `.molt/_build_stats/go.mod`:**

```go
module molt-glue-stats

go 1.21

require user/stats v0.0.0

replace user/stats => /absolute/path/to/project-root/stats
```

**Generated `.molt/_build_stats/server.go`:**

```go
package main

import (
    "bufio"
    "encoding/json"
    "os"
    user "user/stats"    // ← imports YOUR package via the replace directive
)

// ... JSON dispatch loop ...

func _dispatch(req _Req) _Resp {
    switch req.Fn {
    case "mean":
        var a struct{ Data []float64 `json:"data"` }
        json.Unmarshal(req.Args, &a)
        return _Resp{Result: user.Mean(a.Data)}   // ← calls your function
    }
}
```

Your `stats/` directory **must have its own `go.mod`** (molt generates one if absent):

```go
// stats/go.mod  — generated by molt if not present
module user/stats

go 1.21
```

This pattern works for any Go package structure, including packages with their own
dependencies.

## Sample Project 1 — User-written Go package (stdio)

**Scenario:** a Go statistics package called from Python.

### Project layout

```
stats-project/
  moltproject.toml
  stats/
    go.mod          ← "module user/stats" — you write this, or molt init creates it
    stats.go        ← your functions — package stats, NOT package main
  main.py
```

### `stats/stats.go` — your Go package (not package main)

```go
package stats   // ← must NOT be "main"

import (
    "bytes"
    "compress/zlib"
    "math"
)

func Mean(data []float64) float64 {
    if len(data) == 0 { return 0 }
    sum := 0.0
    for _, v := range data { sum += v }
    return sum / float64(len(data))
}

func Stddev(data []float64) float64 {
    if len(data) == 0 { return 0 }
    m := Mean(data)
    v := 0.0
    for _, x := range data { d := x - m; v += d * d }
    return math.Sqrt(v / float64(len(data)))
}

func Histogram(data []float64, buckets int32) []int32 {
    counts := make([]int32, buckets)
    if len(data) == 0 { return counts }
    min, max := data[0], data[0]
    for _, v := range data {
        if v < min { min = v }
        if v > max { max = v }
    }
    if min == max { counts[0] = int32(len(data)); return counts }
    span := max - min
    for _, v := range data {
        idx := int((v-min)/span * float64(buckets-1))
        counts[idx]++
    }
    return counts
}

func Compress(payload []byte) []byte {
    var buf bytes.Buffer
    w := zlib.NewWriter(&buf)
    w.Write(payload)
    w.Close()
    return buf.Bytes()
}
```

  [[tool.molt.glue.fn]]

  args    = [{ name = "payload", type = "bytes" }]

### What `molt sync` generates

**`.molt/_build_stats/go.mod`** (generated):

```
module molt-glue-stats

go 1.21

require user/stats v0.0.0

replace user/stats => /home/you/projects/stats-project/stats
```

**`.molt/_build_stats/server.go`** (generated, then compiled to `.molt/stats_server`):

```go
// Code generated by molt glue. DO NOT EDIT.
package main

import (
    "bufio"
    "encoding/base64"
    "encoding/json"
    "os"
    user "user/stats"
)

type _Req  struct { Fn string `json:"fn"`; Args json.RawMessage `json:"args"` }
type _Resp struct {
    Result any    `json:"result,omitempty"`
    Error  string `json:"error,omitempty"`
}

func main() {
    sc  := bufio.NewScanner(os.Stdin)
    enc := json.NewEncoder(os.Stdout)
    for sc.Scan() {
        var req _Req
        if err := json.Unmarshal(sc.Bytes(), &req); err != nil {
            enc.Encode(_Resp{Error: err.Error()})
            continue
        }
        enc.Encode(_dispatch(req))
    }
}

func _dispatch(req _Req) _Resp {
    switch req.Fn {

    case "mean":
        var a struct{ Data []float64 `json:"data"` }
        json.Unmarshal(req.Args, &a)
        return _Resp{Result: user.Mean(a.Data)}

    case "stddev":
        var a struct{ Data []float64 `json:"data"` }
        json.Unmarshal(req.Args, &a)
        return _Resp{Result: user.Stddev(a.Data)}

    case "histogram":
        var a struct {
            Data    []float64 `json:"data"`
            Buckets int32     `json:"buckets"`
        }
        json.Unmarshal(req.Args, &a)
        return _Resp{Result: user.Histogram(a.Data, a.Buckets)}

    case "compress":
        var a struct{ Payload string `json:"payload"` }
        json.Unmarshal(req.Args, &a)
        raw, _ := base64.StdEncoding.DecodeString(a.Payload)
        out    := user.Compress(raw)
        return _Resp{Result: base64.StdEncoding.EncodeToString(out)}

    default:
        return _Resp{Error: "unknown function: " + req.Fn}
    }
}
```

**`.molt/stats.py`** (generated Python client):

```python
# Code generated by molt glue. DO NOT EDIT.
# Transport: stdio  Lang: go  Module: stats
import json, os, subprocess, threading, atexit, base64

_proc = None
_lock = threading.Lock()

def _ensure_server():
    global _proc
    if _proc is not None:
        return
    _bin = os.path.join(os.path.dirname(__file__), "stats_server")
    _proc = subprocess.Popen(
        [_bin],
        stdin=subprocess.PIPE,
        stdout=subprocess.PIPE,
        stderr=subprocess.DEVNULL,
        bufsize=0,
    )
    atexit.register(lambda: _proc.terminate())

def _call(fn: str, **kwargs):
    _ensure_server()
    with _lock:
        req = json.dumps({"fn": fn, "args": kwargs}) + "\n"
        _proc.stdin.write(req.encode())
        resp = json.loads(_proc.stdout.readline())
    if "error" in resp:
        raise RuntimeError(f"glue error in {fn}(): {resp['error']}")
    return resp["result"]

def mean(data: list[float]) -> float:
    return float(_call("mean", data=data))

def stddev(data: list[float]) -> float:
    return float(_call("stddev", data=data))

def histogram(data: list[float], buckets: int) -> list[int]:
    return _call("histogram", data=data, buckets=buckets)

def compress(payload: bytes) -> bytes:
    res = _call("compress", payload=base64.b64encode(payload).decode())
    return base64.b64decode(res)
```

### `main.py`

```python
import stats   # import the generated module — works after molt sync

data = [88.0, 92.0, 71.0, 95.0, 84.0, 76.0, 89.0, 93.0, 67.0, 88.0]

print(f"mean:   {stats.mean(data):.2f}")
print(f"stddev: {stats.stddev(data):.2f}")

counts = stats.histogram(data, 5)
for i, c in enumerate(counts):
    print(f"  bucket {i+1}: {'█' * c}")

compressed = stats.compress(b"hello world" * 1000)
print(f"\ncompressed {len(b'hello world' * 1000)} bytes → {len(compressed)} bytes")
```

## Sample Project 2 — Existing Go module with its own go.mod

**Scenario:** you have a Go module you already use standalone (with its own `go.mod` and
real module path), and want to expose some functions to Python.

### Layout

```
my-go-lib/
  go.mod           ← module github.com/you/my-go-lib
  go.sum
  crypto/
    hash.go        ← package crypto
  compress/
    zlib.go        ← package compress
  ...
```

### Config

```toml
[[tool.molt.glue]]
module     = "mylib_crypto"
lang       = "go"
src        = "../my-go-lib/crypto"   # relative path to package directory
pkg_module = "github.com/you/my-go-lib/crypto"  # real module path from go.mod
transport  = "stdio"

  [[tool.molt.glue.fn]]
  name    = "hash_sha256"            # exported function name in hash.go
  args    = [{ name = "data", type = "bytes" }]
  returns = "bytes"
```

When `pkg_module` is set, molt uses it in the generated `go.mod`:

```
module molt-glue-mylib_crypto

go 1.21

require github.com/you/my-go-lib/crypto v0.0.0

replace github.com/you/my-go-lib/crypto => /abs/path/to/my-go-lib/crypto
```

And the import in `server.go`:

```go
import user "github.com/you/my-go-lib/crypto"
// ...
return _Resp{Result: user.HashSha256(raw)}
```

> If the module at `../my-go-lib` has external dependencies in its own `go.sum`, molt
> copies `go.sum` into the build dir and runs `go mod tidy` before `go build`.

## Sample Project 3 — Go standard library + third-party module (no local Go code)

**Scenario:** import Go's `crypto/sha256` and a third-party module directly — zero Go
written by you.

```toml
[[tool.molt.glue]]
module    = "gosha"
lang      = "go"
src       = "crypto/sha256"          # stdlib path — no local file or directory
transport = "stdio"

  [[tool.molt.glue.fn]]
  name    = "sum256"
  args    = [{ name = "data", type = "bytes" }]
  returns = "bytes"

[[tool.molt.glue]]
module    = "sha3"
lang      = "go"
src       = "golang.org/x/crypto/sha3"   # third-party; molt runs go get automatically
transport = "stdio"

  [[tool.molt.glue.fn]]
  name    = "sum256"
  args    = [{ name = "data", type = "bytes" }]
  returns = "bytes"

  [[tool.molt.glue.fn]]
  name    = "sum512"
  args    = [{ name = "data", type = "bytes" }]
  returns = "bytes"
```

For **stdlib** (`crypto/sha256`): `src` contains `/` with no file extension and no
leading `./` — molt recognises it as a stdlib package path.

Generated `.molt/_build_gosha/go.mod`:
```
module molt-glue-gosha

go 1.21
// No require — stdlib is always available
```

Generated `.molt/_build_gosha/server.go`:
```go
package main

import (
    ...
    "crypto/sha256"
)

case "sum256":
    var a struct{ Data string `json:"data"` }
    json.Unmarshal(req.Args, &a)
    raw, _ := base64.StdEncoding.DecodeString(a.Data)
    h := sha256.Sum256(raw)            // returns [32]byte
    return _Resp{Result: base64.StdEncoding.EncodeToString(h[:])}
```

For **third-party** (`golang.org/x/crypto/sha3`): `src` starts with a domain — molt
runs `go get` before building.

Generated `.molt/_build_sha3/go.mod`:
```
module molt-glue-sha3

go 1.21

require golang.org/x/crypto v0.0.0-latest
```

`molt sync` runs: `cd .molt/_build_sha3 && go get golang.org/x/crypto/sha3 && go build -o ../../sha3_server .`

### Usage

```python
import gosha, sha3

data = b"Hello, molt glue!"
print(gosha.sum256(data).hex())
print(sha3.sum256(data).hex())
print(sha3.sum512(data).hex())
```

## Sample Project 4 — Rust crate, unix_socket transport

**Scenario:** a persistent compression server in Rust, shared by multiple Python threads.

### `compress_glue.rs` (you write this — thin wrapper, ~20 lines)

```rust
// compress_glue.rs — package name doesn't matter; functions are pub
use flate2::Compression;
use flate2::read::ZlibDecoder;
use flate2::write::ZlibEncoder;
use std::io::{Read, Write};

pub fn deflate(data: Vec<u8>) -> Vec<u8> {
    let mut enc = ZlibEncoder::new(Vec::new(), Compression::default());
    enc.write_all(&data).unwrap();
    enc.finish().unwrap()
}

pub fn inflate(data: Vec<u8>) -> Vec<u8> {
    let mut dec = ZlibDecoder::new(data.as_slice());
    let mut out = Vec::new();
    dec.read_to_end(&mut out).unwrap();
    out
}

pub fn ratio(data: Vec<u8>) -> f64 {
    let compressed = deflate(data.clone());
    compressed.len() as f64 / data.len() as f64
}
```

### `moltproject.toml`

```toml
[[tool.molt.glue]]
module    = "compress"
lang      = "rust"
src       = "compress_glue.rs"   # your functions
crates    = ["flate2 = '1.0'"]   # added to the generated Cargo.toml
transport = "unix_socket"        # persistent daemon; supports concurrent callers

  [[tool.molt.glue.fn]]
  name    = "deflate"
  args    = [{ name = "data", type = "bytes" }]
  returns = "bytes"

  [[tool.molt.glue.fn]]
  name    = "inflate"
  args    = [{ name = "data", type = "bytes" }]
  returns = "bytes"

  [[tool.molt.glue.fn]]
  name    = "ratio"
  args    = [{ name = "data", type = "bytes" }]
  returns = "f64"
```

### What molt generates for Rust

Generated `.molt/_build_compress/Cargo.toml`:
```toml
[package]
name    = "molt-glue-compress"
version = "0.1.0"
edition = "2021"

[dependencies]
serde      = { version = "1", features = ["derive"] }
serde_json = "1"
flate2     = "1.0"    # ← from crates = [...] in config
```

Generated `.molt/_build_compress/src/main.rs` (imports your file via `include!`):

```rust
// Code generated by molt glue. DO NOT EDIT.
use std::io::{self, BufRead, Write};
use serde_json::{json, Value};
use base64::{engine::general_purpose, Engine};

// ── import your functions ────────────────────────────────────────────────────
include!("../../../../compress_glue.rs");   // ← include! pulls in your source

fn dispatch(req: &Value) -> Value {
    let fn_name = req["fn"].as_str().unwrap_or("");
    match fn_name {

        "deflate" => {
            let raw = general_purpose::STANDARD
                .decode(req["args"]["data"].as_str().unwrap()).unwrap();
            json!({ "result": general_purpose::STANDARD.encode(deflate(raw)) })
        }
        "inflate" => {
            let raw = general_purpose::STANDARD
                .decode(req["args"]["data"].as_str().unwrap()).unwrap();
            json!({ "result": general_purpose::STANDARD.encode(inflate(raw)) })
        }
        "ratio" => {
            let raw = general_purpose::STANDARD
                .decode(req["args"]["data"].as_str().unwrap()).unwrap();
            json!({ "result": ratio(raw) })
        }

        _ => json!({ "error": format!("unknown function: {}", fn_name) }),
    }
}

fn main() {
    let stdin  = io::stdin();
    let stdout = io::stdout();
    let mut out = stdout.lock();
    for line in stdin.lock().lines() {
        let req: Value = serde_json::from_str(&line.unwrap()).unwrap();
        let resp = dispatch(&req);
        writeln!(out, "{}", resp).unwrap();
        out.flush().unwrap();
    }
}
```

> **Why `include!` for Rust instead of a proper module?** Because Rust's crate system
> requires a full crate layout to `use` another file as a module. `include!` lets molt
> generate a single-file server that incorporates your code without requiring your file
> to be in a specific directory structure. For larger Rust codebases that already have a
> `Cargo.toml`, use `src = "."` and molt will import the whole crate instead.

### Existing Rust crate (has its own Cargo.toml)

```toml
[[tool.molt.glue]]
module    = "mylib"
lang      = "rust"
src       = "./rust-lib"      # directory with Cargo.toml
transport = "stdio"

  [[tool.molt.glue.fn]]
  name    = "process"
  args    = [{ name = "data", type = "[]f64" }]
  returns = "[]f64"
```

molt adds a dependency on your crate in the generated server's `Cargo.toml`:

```toml
[dependencies]
serde      = { version = "1", features = ["derive"] }
serde_json = "1"
mylib      = { path = "../../../../rust-lib" }   # ← your crate via path dep
```

And imports it normally in the generated server:

```rust
use mylib::process;
// ...
"process" => { json!({ "result": process(data) }) }
```

## Sample Project 5 — Custom Nim driver

**Scenario:** add glue support for a language molt doesn't ship built-in.

### Register the Nim driver (once, globally)

```sh
molt glue-driver add nim \
    --build "nim c -d:release --hints:off -o:{output} {server_file}" \
    --lib-setup "nimble install {import_path}"
    --server-template ~/.molt/glue-templates/nim-server.nim.tmpl \
    --client-template ""    # empty = use molt's built-in Python client (recommended)
```

`~/.molt/glue-templates/nim-server.nim.tmpl` (you write once):

```nim
# Code generated by molt glue. DO NOT EDIT.
import json, os, strutils, base64
include "{{.SrcAbsPath}}"   {# ← includes your Nim file #}

proc dispatch(req: JsonNode): JsonNode =
  let fn = req["fn"].getStr()
  {{range .Fns}}
  if fn == "{{.Name}}":
    {{range $i, $a := .Args}}
    let {{$a.Name}} = {{nimDecode $a.Type (printf "req[\"args\"][\"%s\"]" $a.Name)}}
    {{end}}
    let result = {{.Name}}({{range $i,$a := .Args}}{{if $i}}, {{end}}{{$a.Name}}{{end}})
    return %* {"result": {{nimEncode .Returns "result"}}}
  {{end}}
  return %* {"error": "unknown function: " & fn}

while true:
  let line = stdin.readLine()
  if line.len == 0: break
  let req  = parseJson(line)
  let resp = dispatch(req)
  echo $resp
  stdout.flushFile()
```

### Use in a project

```toml
[[tool.molt.glue]]
module    = "nimstats"
lang      = "nim"              # uses the registered Nim driver
src       = "stats.nim"        # your Nim file with functions
transport = "stdio"

  [[tool.molt.glue.fn]]
  name    = "sum"
  args    = [{ name = "data", type = "[]f64" }]
  returns = "f64"
```

`molt sync` → renders `nim-server.nim.tmpl` with your fn declarations → runs
`nim c -d:release -o:.molt/nimstats_server .molt/_build_nimstats/server.nim` →
generates `.molt/nimstats.py` using the built-in Python client template.

## Transport comparison

| Transport | Server lifecycle | Concurrency | Best for |
|---|---|---|---|
| `stdio` | subprocess per Python process | serial (lock) | scripts, notebooks, simple use |
| `unix_socket` | persistent daemon | concurrent | web apps, parallel Python code |
| `tcp` | persistent daemon, network-addressable | concurrent | Docker, distributed setups |

## How `molt sync` orchestrates glue

```
molt sync
│
├─ [existing]  uv dependency resolution + package install
├─ [existing]  Cython / Rust PyO3 / kernel module builds
│
└─ [glue]  For each [[tool.molt.glue]] block:
   │
   ├─ Hash(src files + config)
   │      → check ~/.molt/native/<hash>/
   │
   ├─ Cache HIT  → symlink cached server binary + copy *.py → done
   │
   └─ Cache MISS:
       │
       ├─ FindDriver(lang)
       │      → load from ~/.molt/glue-drivers.yaml
       │
       ├─ Prepare build dir  (.molt/_build_<module>/)
       │   ├─ Go:   write go.mod with "replace <pkg> => <abs_src_path>"
       │   │        if third-party src: run "go get <import_path>"
       │   ├─ Rust: write Cargo.toml with path dep or include!
       │   └─ Other: run lib_setup_cmd if src is a library path
       │
       ├─ Render server template
       │      → .molt/_build_<module>/server.{go,rs,nim,...}
       │
       ├─ Run build_cmd
       │      → go build -o .molt/<module>_server .molt/_build_<module>/
       │      → cargo build --release ...
       │      → nim c ...
       │
       ├─ Cache result  → ~/.molt/native/<hash>/<module>_server
       │
       ├─ Generate .molt/<module>.py   (Python client — always built-in template)
       ├─ Generate .molt/<module>.pyi  (typed stubs)
       └─ Write ~/.molt/native/<hash>/meta.json
```

`.molt/` is already on `PYTHONPATH` (set by the existing syspath mechanism), so
`import stats` works immediately after `molt sync`.

## Type reference

| Glue type | Go | Rust | Python | JSON wire |
|---|---|---|---|---|
| `i32` | `int32` | `i32` | `int` | number |
| `i64` | `int64` | `i64` | `int` | number |
| `f32` | `float32` | `f32` | `float` | number |
| `f64` | `float64` | `f64` | `float` | number |
| `bool` | `bool` | `bool` | `bool` | boolean |
| `string` | `string` | `String` | `str` | string |
| `bytes` | `[]byte` | `Vec<u8>` | `bytes` | base64 string |
| `[]i32` | `[]int32` | `Vec<i32>` | `list[int]` | array |
| `[]f64` | `[]float64` | `Vec<f64>` | `list[float]` | array |
| `[]string` | `[]string` | `Vec<String>` | `list[str]` | array |
| `json` | `any` | `serde_json::Value` | `Any` | any JSON |

For **library imports** where the return type doesn't fit these primitives
(e.g. `*http.Response`), use `returns = "json"` and molt generates an adapter function
that extracts the useful fields into a dict.

---

## Comparison with the `.so` approach

| | `.so` / FFI | Transport Glue |
|---|---|---|
| Supported types | C-ABI primitives only | All JSON-serialisable types |
| Go functions | Only `//export`-able (cgo) | Any exported function |
| Rust functions | Only `#[no_mangle] extern "C"` | Any `pub` function |
| Go stdlib | ✗ (most types not exportable) | ✓ |
| Rust `async fn` | ✗ | ✓ (server handles async internally) |
| Structs / slices | Manual C marshalling | Automatic via JSON |
| Setup complexity | Build flags, linker scripts | `molt sync` |
| Performance | In-process, zero copy | One JSON encode/decode + IPC |
| **When to prefer** | CPU-bound inner loops, huge arrays | Everything else |
